# Проверки на живых сайтах

Не ломаются ли интерактивные элементы настоящих сайтов после перевода. В `tests/run.sh`
не входят: сеть и сайты нестабильны. Снимки — `tests/shots/sites/`.

## Что нужно

- Chrome 138+ (проверено на 157; путь — `CHROME_PATH`, по умолчанию `/usr/bin/google-chrome`), Node 18+.
- `playwright-core`: берётся из `PLAYWRIGHT_CORE`, из кэша npx (`~/.npm/_npx/9833c18b2d85bc59/node_modules`) или из
  `~/.cache/ht-tests/node_modules` (`cd ~/.cache/ht-tests && npm i playwright-core`).
- Профиль Chrome, где уже скачаны модели встроенного переводчика en↔ru (по умолчанию `~/.cache/ht-tests/profile-store`).
  Скрипт копирует его во временную папку и в конце удаляет копию. Оригинал не трогает.
- Только тестовый профиль: перед каждым сайтом скрипт очищает cookies браузера целиком. Профиль Chrome человека
  (`~/.config/google-chrome…`, `~/.config/chromium`) в `--profile` скрипт не примет.

## Запуск

```
node tests/sites/run.js --list                    # сайты
node tests/sites/run.js                           # все сайты
node tests/sites/run.js --only wikipedia --json ~/.cache/ht-tests/sites.json
node tests/sites/run.js --profile DIR             # свой тестовый профиль (не копируется и не удаляется)
node tests/sites/run.js --ext DIR                 # расширение из DIR (по умолчанию hover-translate рабочего дерева)
node tests/sites/run.js --base-only               # только без расширения: отладка селекторов сайта
node tests/sites/run.js --trace-lang --only wikipedia   # какой язык детектор дал каждому куску (отладочная копия)
node tests/sites/run.js --no-baseline --keep      # без прогона без расширения; не удалять временную папку
node tests/sites/run.js --shots DIR               # куда класть снимки (по умолчанию tests/shots/sites)
node tests/sites/run.js --headed                  # Chrome с окном (по умолчанию без интерфейса)
```

**`--ext DIR`** — папка расширения (с `manifest.json`). Скрипт копирует её во временную папку и ставит копию через
CDP `Extensions.loadUnpacked`; сама `DIR` не меняется. Если рядом со снимком лежит `tests/lib/live.js`
(`DIR/../tests/lib/live.js`), берётся он — слой нашего интерфейса на странице того же коммита.

**`--trace-lang`** — в копию `content.js` (не в рабочее дерево) после определения языка в `chromeTranslate`
вставляется `console.debug("[ht-lang]", {text, src, kind, guess, byBlock})`. В JSON у фазы page появляется
`page.langs`: сколько кусков на каком языке и примеры кусков не на языке страницы (`угадан` — язык короткого куска
угадан по паре слов, модель для него не качается). Якорь вставки — строка `const src = d.lang;`. Если её нет или
она не одна, скрипт остановится с ошибкой: `chromeTranslate` изменился, и якорь надо поправить.

**Проверять коммит, пока рабочее дерево правят**: снимок расширения и
`tests/lib` из HEAD и `--ext` на него. `tests/lib/live.js` рядом со снимком подхватывается сам (слой нашего интерфейса
на странице — того же коммита):

```
mkdir -p ~/.cache/ht-tests/s7-sites/head
git archive HEAD hover-translate tests/lib | tar -x -C ~/.cache/ht-tests/s7-sites/head
HT_TMP=~/.cache/ht-tests/s7-sites node tests/sites/run.js --ext ~/.cache/ht-tests/s7-sites/head/hover-translate \
  --profile ~/.cache/ht-tests/sites-profile --json ~/.cache/ht-tests/s7-sites/sites.json
```

`--profile` — уже готовая копия профиля (`~/.cache/ht-tests/sites-profile`: en↔ru, ro, fr, it скачаны); без него
скрипт копирует `profile-store` во временную папку (≈0,9 ГБ) и удаляет копию в конце.

Временные файлы лежат в `$HT_TMP` (по умолчанию `~/.cache/ht-tests`), в папке `ht-sites-XXXX`. Там же копия
профиля, копия расширения и чистый профиль для прогона без расширения. Папка удаляется в конце и по Ctrl+C.

По каждому сайту два прогона с одинаковыми действиями: без расширения (какие ошибки консоли у сайта и так есть) и с
расширением. Перед каждым сайтом cookies браузера и хранилище сайта очищаются — баннеры согласия появляются как в
первый раз и с сохранённым профилем. Шаги: [prepare: баннер] → Shift на `site.key` → действия → «Перевести страницу» →
снимки светлой и тёмной темы → действия → [scroll] → Esc → действия, проверки → снова «Перевести страницу» и переход.
За время перевода страницы собираются все показанные уведомления: «Страница переведена» висит 3 с. Доля перевода
считается двумя способами: по первым 4000 знакам `main` и по тексту, видимому на экране (`VIS_TEXT`).
Перед Esc записывается, что `content.js` счёл бы «открытым у сайта» (`SITE_OPEN` повторяет `siteOpen`). Если там
что-то есть, Esc уходит сайту, и оригинал не возвращается. После Esc проверяется: элемент `key` вернул прежний текст
(без учёта пробелов и переводов строк: у скрытого элемента `innerText` — это `textContent` с исходными пробелами),
текст, вписанный сайтом, не затёрт (`MUT_*`), и не осталось ли перевода (`RESID`). `MUT_*` запоминает у каждого узла,
что вписал сайт (`first`), и откат нашего перевода нового содержимого (MutationObserver расширения перевёл, Esc вернул
текст сайта) считает «откачен», а не «изменились» — если перевод сменил письменность, как в `RESID`. Перед переходом записывается состояние перевода (`navPage`). После
перехода — состояние, доли и плавающая кнопка (`fabInfo`: есть ли хост, нарисован ли кружок). Если переход прошёл
без перезагрузки (SPA, тот же `performance.timeOrigin`), то же самое повторяется через 12 с: новое содержимое
переведённой страницы должно перевестись само. Новые ошибки консоли — те, которых нет в прогоне без расширения;
у наших в стеке `chrome-extension://`.

Поля сайта — в шапке `sites.js`. `target` должен быть из таблицы целевых языков `shared.js` (`HT_TARGET_LANGS`):
`"EN"` — только язык оригинала, целью годится `"EN-US"`/`"EN-GB"`. С другим кодом скрипт сразу останавливается
(настройку с таким кодом расширение молча отвергает, и перевод шёл бы на RU). Из нового: `key` — селектор или функция-поиск (элемент без устойчивого селектора,
баннер, которого может не быть); `phases` у действия — только в этих фазах (баннер cookie переводим клавишей и
жмём «Accept» в переведённом — один раз, в фазе `key`); `navMain` — основной текст после перехода; `H.state()` —
состояние вкладки у расширения; `H.evFrame(re, fn)` — проверка внутри iframe без «действия пользователя»;
`escInField(H)` — Esc в поле сайта (проверяет, что перевод страницы не откатился); `H.escMenu(trigger, isOpen)` —
Esc при открытом меню сайта, фокус не в поле: меню закрывает сайт, перевод остаётся (`{ siteKeepsOpen: true }` —
сайт и без расширения по Esc меню не закрывает: проверяется только перевод).

## Важно

- Проверки на странице идут только через CDP `Runtime.evaluate` без жеста (`lib.js → pageKit.ev`), щелчки и клавиши —
  настоящие. `page.evaluate`, `page.$` и `locator` у Playwright дают странице «действие пользователя», и встроенный
  переводчик Chrome начинает качать модели там, где у человека он попросил бы щелчок.
- Playwright по умолчанию ломает встроенный переводчик. `lib.js → launchChrome` убирает `--disable-component-update`,
  `--disable-background-networking` и `OptimizationHints` (список повторяет playwright-core 1.66).
- `locale` в Playwright не задаётся: он сузил бы `navigator.languages` до одного языка, и пара en→ru стала бы «скрытой».
- Строка агента — как у обычного Chrome той же версии, без «HeadlessChrome» (`lib.js → UA`):
  проверяем ту страницу, что сайт отдаёт человеку. С «HeadlessChrome» часть сайтов отдаёт 403 или капчу.
